## Почему ноль

Это не экономия ради экономии и не незавершённая работа. Разбор строился так,
чтобы каждая находка доказывалась бесплатным эндпоинтом:

| Что нужно было узнать | Чем узнали | Цена |
|---|---|---|
| Какие модели существуют и что принимают | `GET /capabilities` | 0 ₽ |
| Сколько стоит конкретный вызов | `POST /generate/estimate` | 0 ₽ |
| Расходятся ли каталог и прайс | `GET /capabilities` + `GET /prices` | 0 ₽ |
| Ловит ли платформа некорректное тело | `POST /generate/estimate` без `strict` | 0 ₽ |
| Достижим ли `strict` через MCP | `tools/list` + `tools/call` на `estimate_generation` | 0 ₽ |
| Работает ли схема подписи вебхуков | `POST /webhook-test` | 0 ₽ |
| Каков баланс и дневной лимит | `GET /balance`, `GET /me` | 0 ₽ |

Ключевой факт: **`/generate/estimate` бесплатен и точен**. Он оценил все
проверенные модели, включая те, которых нет в `/prices`, и тарифы, которых нет в
`tiers`. Девять смет подряд — баланс не сдвинулся ни на копейку.

## Проверка C — `strict: true`, стоила 0 ₽

Единственное утверждение из вашей документации, которое нельзя было подтвердить
бесплатно:

> «Pass `strict=true` to reject unknown/incompatible params before debit.»
> — `capabilities.features.strict_mode`

Проверялось на самой дешёвой модели платформы, чтобы цена ошибки была
минимальной. Отправлено ровно один раз, с `idempotency_key`, без повторов:

```json
{"type": "image", "model": "z-image", "prompt": "a plain grey square, test pattern",
 "bogus_param": 1, "strict": true, "idempotency_key": "mainager-exp-c-strict-422-001"}
```

Ответ — HTTP **422**:

```json
{"error": "unknown_or_incompatible_params", "model": "z-image",
 "rejected": ["bogus_param"],
 "hint": "These params are not accepted by model \"z-image\". Allowed: type, model,
          prompt, callback_url, strict, idempotency_key, aspect_ratio.",
 "valid_params": ["type","model","prompt","callback_url","strict",
                  "idempotency_key","aspect_ratio"]}
```

Баланс до — 600 ₽, после — 600 ₽. `daily_spend_today`: 0 → 0.

**Вывод: заявление верно.** `strict` действительно отклоняет несовместимые
параметры до списания. Это переводит `features.strict_mode` из «ваше
утверждение» в «наш замер» и делает находку №1 весомее, а не слабее: механизм
защиты рабочий, поэтому его отсутствие в MCP-схеме — упущенная возможность, а не
несуществующая функция.

Побочно: тело ответа 422 содержит `valid_params` — полный список допустимых
параметров модели. Это лучший источник для валидации на стороне клиента, чем
`optional` из каталога.

## Проверка D — то же тело без `strict`, стоила 1,2 ₽

Вторая половина того же механизма. Тело идентичное, флаг убран:

```json
{"type": "image", "model": "z-image", "prompt": "a plain grey square, test pattern",
 "bogus_param": 1, "idempotency_key": "mainager-exp-d-nostrict-001"}
```

Ответ — HTTP **200**:

```json
{"status": "processing", "generation_id": 26001, "cost": 1.2,
 "balance_after": 598.8, "ignored_params": ["bogus_param"]}
```

Генерация дошла до конца за ~36 секунд: `status: complete`, `refunded: false`,
картинка отдана по подписанной ссылке. Баланс 600 → 598,8 ₽,
`daily_spend_today` 0 → 1,2.

**Пара C+D замыкает механизм:**

| | Флаг | HTTP | Параметр | Списано |
|---|---|---|---|---|
| C | `strict: true` | 422 | отклонён, вызов не состоялся | 0 ₽ |
| D | нет флага | 200 | молча отброшен, генерация выполнена | 1,2 ₽ |

Оба ваших утверждения верны буквально. `strict` спасает деньги, его отсутствие
их тратит, и разница определяется одним булевым полем, которого нет в схеме
MCP-инструментов. Именно поэтому находка №1 — про упущенную возможность, а не
про отсутствующую функцию.

## Проверка идемпотентности — стоила 0 ₽

`idempotency_key` заявлен в описании `generate_content`: «повторный вызов с тем же
ключом не спишет деньги дважды». Проверялось повторной отправкой **того же самого
тела**, что и в проверке D, с тем же ключом:

```json
{"status": "complete", "generation_id": 26001,
 "task_id": "ea8857df531b5347a7589e40bf306d50",
 "cost": 1.2, "balance_after": 598.8, "replayed": true}
```

Тот же `generation_id`, тот же `task_id`, баланс 598,8 → 598,8. Списания нет.

Отдельно стоит отметить поле **`replayed: true`** — явный признак того, что ответ
отдан из истории, а не выполнен заново. Многие API этого не сообщают, и клиенту
приходится догадываться по совпадению идентификатора. Здесь сделано аккуратно.

## Что осталось непроверенным без платного вызова

1. **Влияет ли `duration` на длительность результата при закреплённом тарифе.**
   На цену — измеренно не влияет. Совпадает ли фактическая длина ролика с
   суффиксом тарифа, проверяется только `ffprobe` по готовому файлу.
2. **Качество результата** как таковое — вся плоскость ③ в части OCR и проверки
   кадров.

## План платной проверки

Стоимость каждого пункта посчитана сметой на реальных телах запросов, а не взята
из прайса. Худший случай — **74,4 ₽**, укладывается в цель «меньше 100 ₽».

| # | Что закрывает | Тело | Цена |
|---|---|---|---|
| ~~C~~ | ~~Правда ли `strict: true` даёт 422 до списания~~ | **выполнено 28.07, HTTP 422, списано 0 ₽** | **0 ₽** |
| ~~D~~ | ~~То же тело без `strict`~~ | **выполнено 28.07, HTTP 200, `ignored_params`, списано 1,2 ₽** | **1,2 ₽** |
| A | Чек по документированной ловушке | `grok-ttv`, `duration: 5`, `image_input`, без `strict` | 36 ₽ |
| B | Чек по тому же намерению, но маршрутизированному | `grok-itv`, `duration: 5`, `image_urls`, `strict` | 36 ₽ |

**C и D выполнены** и вместе обошлись в 1,2 ₽ вместо запланированных 2,4 ₽:
C не стоила ничего, потому что утверждение оказалось верным. Механизм доказан
полностью. Осталось два пункта на 72 ₽ — только ради наглядных чеков в README,
доказательной нагрузки они уже не несут.

Отдельно стоит отметить: пара чеков A+B изначально планировалась на закреплённых
тарифах и обошлась бы примерно в 392 ₽. На базовом идентификаторе при
`duration: 5` — 72 ₽. **Находка про тарифы окупила эксперимент, который её
демонстрирует.**

## Модельные оценки экономии

Помечено явно: это **моделирование**, а не замер. Допущения указаны в строке.

| Сценарий | Расчёт | Экономия |
|---|---|---|
| 5-секундный ролик через базовый идентификатор вместо примера из документации | 316 − 36 | 280 ₽ на вызов |
| 15-секундный ролик по фактической цене вместо выбора по полю `price` | 316 − 120 | 196 ₽ на вызов |
| Озвучка 1000 символов дешёвой моделью вместо выбранной по `/prices` | 13 − 8 | 5 ₽ на вызов |
| Отклонение тела с `image_input` на видео-модели до списания | 36 − 0 · 196 − 0 | от 36 ₽ (базовый id, 5 с) до 196 ₽ (закреплённый тариф) |

Умножение на объём намеренно не делается: данных по трафику вашего коннектора у
нас нет, а выдуманное число здесь испортило бы всё остальное.
