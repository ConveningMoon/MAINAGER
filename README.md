# MAINAGER

[![ci](https://github.com/ConveningMoon/MAINAGER/actions/workflows/ci.yml/badge.svg)](https://github.com/ConveningMoon/MAINAGER/actions/workflows/ci.yml)

**Наглядный разбор: [conveningmoon.github.io/MAINAGER](https://conveningmoon.github.io/MAINAGER/)**
· [Проведённые проверки](https://conveningmoon.github.io/MAINAGER/tests.html)

Контур управления между автономным агентом и генеративным API: что вызвать,
стоит ли вызывать, сколько это стоило и был ли результат пригоден.

> Ваш агент — не проблема. Проблема в том, что между агентом и деньгами клиента
> нет контура управления.

Это не демо генерации контента. Это разбор вашего API с работающей реализацией
того слоя, которого в нём не хватает: девять мест, где документация, каталог и
прайс расходятся с тем, что реально списывается. Все девять измерены запросами,
а не вычитаны.

**Весь разбор стоил 1,2 ₽ из выданных 600.** Девять находок из девяти доказаны
бесплатными эндпоинтами; единственная пара платных вызовов ушла на проверку
того, что иначе проверить нельзя, и обошлась в стоимость одной картинки.
Это часть вывода: почти всё, что описано ниже, ваш API рассказывает о себе сам
и бесплатно — просто в полях, на которые агент не смотрит.

## Что нашлось

| | Находка | Цена вопроса |
|---|---|---|
| 1 | В MCP-коннекторе флаг `strict` не объявлен ни в одной из девяти схем | сценарий по умолчанию — незащищённый, 196 ₽ за вызов |
| 2 | `/generate/estimate` отдаёт `valid: true` вместе с `rejected: ["image_input"]` | поле, по которому агент ветвится, говорит «годен» |
| 3 | Пример из вашей документации закрепляет тариф и отключает авто-выбор | **8,8×** за один и тот же 5-секундный ролик |
| 4 | `price` в каталоге — цена при дефолтных параметрах, а не цена вызова | занижение до 12× |
| 5 | `/capabilities` и `/prices` расходятся по 13 идентификаторам, и за один день расхождение менялось трижды | потолок расходов занижен на 38% |
| 6 | Числа в `/prices` в трёх разных единицах измерения | список переворачивает порядок «что дешевле» |
| 7 | `valid` смешивает «тело корректно» и «хватает денег» | не отвечает ни на один из двух вопросов |
| 8 | Ответ агента бесплатен, ответ автоответчика за него — 10 ₽, решают 4 секунды | латентность агента — строка в P&L клиента |
| 9 | Модели с `-edit` дороже базовых, хотя обычная модель правит картинку по цене генерации | 45 ₽ против 9 ₽ за ту же операцию |

Подробности с цитатами из вашей документации — в [`FINDINGS.md`](FINDINGS.md).
Те же цифры в виде графиков — на [странице разбора](https://conveningmoon.github.io/MAINAGER/).

## Что из этого построено

**Построено и покрыто тестами — две плоскости:**

```
Агент / оператор
      │  Intent
      ▼
┌──────────────── MAINAGER ────────────────┐
│ ① PREFLIGHT   компилятор намерения       │
│    каталог → выбор модели → валидное тело│
│    цена только через estimate            │
│    смета сценария целиком                │
│              │                           │
│ ② GUARD      детерминированный стоп-кран │
│    потолки · L0–L3 · детектор циклов     │
│    дедупликация · аудит-лог с хеш-цепью  │
└──────────────┬───────────────────────────┘
               ▼  Vibe Agent API
```

Поверх них работают три элемента: **прокси перед вашим MCP**, **отчёт о
перерасходе** по истории генераций и **транспорт** с ретраями и лимитами
(платный вызов повторяется только при наличии ключа идемпотентности).

**Спроектировано, но не построено — ещё две:** Postflight (проверка результата
через OCR и `ffprobe`) и Fastpath (входящий канал до 4 секунд). Причины в
[`DESIGN.md`](DESIGN.md), и они конкретные: первая требует внешних бинарников и
весов моделей и не добавляет к разбору API ни одного факта; вторую нечего
показывать — на тестовом аккаунте нет входящего трафика.

### Плоскость ① — Preflight

Реестр моделей **генерируется** из `/capabilities`, а не переписывается руками:
каталог уже отдаёт `required`, `optional`, `enums`, `limits`, `tiers`,
`tier_prices`, `mutually_exclusive` по каждой модели. Компилятор подставляет то
поле под исходную картинку, которое объявила выбранная модель, и отказывается
собрать тело, за которое заплатят и которое проигнорируют.

Цена никогда не считается локально: только `POST /generate/estimate`, который
оказался единственным полным источником — он корректно оценивает и модели,
которых нет в `/prices`, и тарифы, которых нет в `tiers`.

### Плоскость ② — Guard

Проверки идут от самой дешёвой к самой дорогой: стоп-кран, уровень автономии,
режим тени, потолки, детектор циклов, семантическая дедупликация.
**Языковая модель не участвует ни в одной из них** — во входящем канале есть
4 секунды до того, как ответит платный автоответчик платформы.

Аудит-лог — цепочка хешей: каждая запись содержит хеш предыдущей, поэтому
выборочное редактирование постфактум обнаруживается.

### Прокси для MCP

`mcp_server.py` — не ещё один MCP-сервер, а прокси перед вашим. Пробрасывает все
девять инструментов, добавляет `strict` в схему двух из них, пересчитывает
вердикт по `rejected` вместо `valid`, держит потолок расходов и переписывает
закреплённый тариф на базовый, сообщая об этом в ответе. Проверено на живом
сервере: `grok-itv-20` + `duration 5` → `grok-itv`, смета **36 ₽ вместо 316 ₽**.

## Быстрый старт

```bash
python -m venv .venv && . .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env          # вписать токен вида oc_...

mainager capabilities         # выгрузить каталог моделей
mainager drift                # сверить каталог с прайсом
mainager overspend --from-file data/generations_synthetic.json
mainager drift --json         # одна строка для журнала наблюдений
mainager verify               # заново проверить каждую находку прямо сейчас
```

Все команды используют только бесплатные эндпоинты.

### Проверить находки самостоятельно

`mainager verify` — не отчёт, а код: он заново отправляет запрос за каждым из
девяти пунктов FINDINGS.md к живому API и печатает, совпало ли измерение с тем,
что записано. Баланс печатается до и после — команда сама себя проверяет на то,
что ничего не потратила.

```bash
pip install -e ".[mcp,dev]"   # mcp нужен для проверки находки №1
mainager verify
```

Выход — `0`, если все девять сошлись, иначе `1` с указанием, какие именно
разошлись и как. Цены у площадки меняются в течение дня (см. находку №4), так
что расхождение здесь — не обязательно ошибка с нашей стороны, это и есть смысл
команды: показать, что изменилось, а не заявить об этом на слово.

Расхождение каталога и прайса не статично — за один день оно менялось трижды.
Поэтому `mainager drift --json` пишет одну строку наблюдения, а GitHub Actions
запускает его ежедневно и дописывает в [`data/drift-log.jsonl`](data/drift-log.jsonl),
пропуская дни, когда ничего не изменилось. Через пару недель это уже не снимок,
а временной ряд по чужой платформе.

Для стоп-крана и дедупликации нужны Redis и PostgreSQL с pgvector:

```bash
docker compose up -d
pytest                        # интеграционные тесты подхватят их сами
```

Без них проект работает на процессных реализациях тех же портов — для разработки
этого достаточно, для продакшена нет: стоп-кран, который видит один процесс,
стоп-краном не является.

## Честные ограничения

- **Эмбеддер** для дедупликации — хеш символьных триграмм, выбран чтобы не
  тянуть модель, GPU и сеть. Ловит поверхностное сходство, **не смысл**: две
  перефразировки без общих триграмм не совпадут. В реальном развёртывании на его
  место встаёт нормальная модель за тем же протоколом `Embedder`, и порог
  придётся перекалибровать.
- **История генераций** в `data/generations_synthetic.json` синтетическая. На
  аккаунте, где делался разбор, генераций нет вовсе — команда `overspend`
  работает против любого аккаунта, где они есть.
- Записи, для которых нельзя восстановить исходные параметры, помечаются как
  непроанализированные и **исключаются из итога**, а не угадываются.
